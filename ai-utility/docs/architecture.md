# scratch-cli Architecture

## 概要

この文書は、Codexへの移行後のscratch-cliの設計、実装状況、開発方針を管理する。

## 現在の実装状況

- Bun、TypeScript、yargsを使用した `scc` CLIを実装している。
- `login`、`logout`、`session`、`user`、`search project`、`python`、`version` コマンドを実装している。`account` はログイン中のアカウントの詳細を `user` の既存取得処理で表示する。
- `explore project|studio` でScratchの傾向（既定）または人気の一覧を取得する。`--mode`、`--limit`（1～40）、`--offset` を指定できる。プロジェクトのみ `--category` で all（既定）/animations/art/games/music を選べる。
- `notifications`（別名 `messages`）で現在のScratchアカウントの通知を閲覧する。`--limit`（1～40）、`--offset` を指定できる。
- `profile [section] [--user <username>]` でプロフィール本文や公開一覧（共有作品、お気に入り作品、参加スタジオ、フォロー中のスタジオ、フォロー中のユーザー、フォロワー、コメント）を閲覧する。`--user` 省略時は保存済みセッションのユーザーを使用する。`--list` は利用可能なセクションを通信なしで表示する。旧形式 `profile <username> <section>` も受け付ける。
- zsh向けの静的補完定義を `scc completion` から出力できる。
- Scratchの認証情報は `~/.config/scc/config.json` に保存し、ファイルを所有者のみ読み書き可能な権限で作成する。
- Scapiは `~/.config/scc/python/.venv` の専用Python仮想環境で利用する。
- TypeScriptとPython間では、標準出力のJSONを介して検索結果およびユーザー情報を受け渡す。
- オフライン単体テストにはBunの組み込みテストランナーを使用する。通常のテストではScratch APIへアクセスしない。

## 開発中の機能

- CLIのエラー処理と入力検証の統一。
- 認証情報とログアウト処理の安全性向上。
- オフライン単体テストの拡充。

## 今後の開発計画

- Scratchプロジェクトをテキスト形式で編集し、sb3との相互変換や同期を行う機能。
- 複数Scratchアカウントの認証情報を分離して管理する機能。
- プロジェクトやスタジオに対するコマンドの拡充。

これらは計画中であり、実装済みまたは着手指示済みの機能として扱わない。

## 設計上の決定事項

- CLIの利用者向けメッセージは英語で統一する。
- コマンドの失敗時はメッセージを標準エラーに出力し、終了コードを非0にする。
- yargsの引数エラーではヘルプを標準出力に表示し、最後の `Error: ...` 行のみ標準エラーに出力する。
- 必須の位置引数が不足した場合は、不足している引数名と説明（選択肢があればその値）をエラー行に示す。
- パスワードはCLIオプションで受け取らず、対話端末から非表示入力する。非対話環境では入力を待たず、安全に失敗する。
- セッションIDは子プロセスのコマンドライン引数に含めず、標準入力でPython側へ渡す。
- 認証情報をログやエラーメッセージに含めない。
- ログアウト成功後は、使用していたセッションCookieを送ってセッションが無効になったことを確認してからローカル認証情報を削除する。
- 外部APIを使う結合テストは通常の単体テストから分離する。
- ExploreではScapiの `explore_projects` / `explore_studios` を認証なしで使用し、件数を40以下に制限して1回のAPIリクエストに収める。プロジェクトのカテゴリは `explore_projects` の `query` に渡し、all は `*` に変換する。スタジオにはカテゴリを適用しない。
- 通知はScapiの `Session.get_messages()` で取得し、既読化する `clear_message()` は呼び出さない。セッション検証と通知取得を各1回行い、ユーザー名を結果に表示する。
- プロフィールの公開一覧は原則としてScratch APIのJSONを1回取得して検証する（Scapi 3.2.4 の作品オブジェクト変換が一部レスポンスで失敗するため）。`about` は公開プロフィールHTMLを1回取得して表示名、ユーザー種別、参加日、国、自己紹介、近況、最近の活動を抽出し、注目のプロジェクトと可変ラベルは Scapi の `User.get_featured()` で1回追加取得する。画像URLからユーザーIDを取得できない場合は不明として扱う。フォロー中のスタジオは公開HTMLページ1回を解析し、同じスタジオの複数リンクからタイトルを補完する。コメントは1ページだけ取得し、同ページの返信キャッシュを表示する。`--user` 省略時のみセッション検証を追加し、認証情報は標準入力でPythonに渡す。自動巡回しない。

## 未解決の問題

- 複数アカウント用の設定形式と切り替え操作は未設計。
- Scratch API呼び出しの共通タイムアウト、429処理、再試行方針は未実装。
- Python仮想環境とScapiのセットアップ処理には、更新前の確認やバージョン固定方針の検討が必要。
- 認証・検索・ユーザー取得について、HTTPおよびPythonプロセスをモックしたテストが不足している。
